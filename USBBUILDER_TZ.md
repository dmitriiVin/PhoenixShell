# Техническое задание: UsbBuilder для PhoenixShell

## 1. Назначение

UsbBuilder — отдельное Windows-приложение для создания загрузочной флешки с двумя разделами и встроенным PhoenixShell.

Программа должна:
- принимать на вход папки с программами, драйверами, образами Windows и ресурсами PhoenixShell;
- автоматически подготавливать загрузочную флешку с 2 разделами;
- разворачивать PhoenixShell в загрузочную среду WinPE;
- размещать данные на втором NTFS-разделе;
- собирать готовый загрузочный USB-накопитель без ручной постобработки.

## 2. Цель

Упростить подготовку сервисной флешки для установки Windows и обслуживания ПК. Пользователь выбирает исходные папки, а UsbBuilder сам:
- разметит флешку;
- создаст загрузочный WinPE-раздел;
- скопирует PhoenixShell;
- развернёт программы, драйверы и образы Windows на второй раздел;
- подготовит автозапуск PhoenixShell при загрузке.

## 3. Связь с PhoenixShell

UsbBuilder должен работать в связке с PhoenixShell и использовать его соглашения по структуре данных.

Поддерживаемые сущности PhoenixShell:
- `Tools/` — программы и утилиты;
- `Drivers/` — драйверы по категориям;
- `Windows/` — образы Windows (`.wim`, `.esd`, `.iso`);
- `PhoenixShell/` — обои, конфиги, темы, ресурсы;
- `InstallerAgent/` — данные для первого запуска установленной Windows;
- `tool.json` — описание инструментов;
- `settings.json` и `shortcuts.json` — настройки и ярлыки.

UsbBuilder должен понимать эту структуру и переносить её на USB-накопитель без ручной настройки.

## 4. Основной сценарий использования

1. Пользователь запускает UsbBuilder в Windows.
2. Выбирает USB-накопитель.
3. Выбирает источник данных:
   - папку с программами;
   - папку с драйверами;
   - папку с образами Windows;
   - папку с ресурсами PhoenixShell;
   - при необходимости готовую сборку PhoenixShell.exe.
4. Выбирает параметры разметки флешки.
5. Нажимает кнопку создания.
6. UsbBuilder:
   - очищает флешку;
   - создаёт 2 раздела;
   - делает первый раздел загрузочным;
   - разворачивает WinPE и PhoenixShell;
   - копирует данные на второй раздел;
   - записывает конфиги автозапуска;
   - завершает подготовку.

## 5. Архитектура приложения

UsbBuilder должен быть отдельным приложением, построенным на:
- C++20;
- Qt6 Widgets;
- CMake;
- MSVC 2022.

QML использовать нельзя.

Рекомендуемые модули:
- `Core` — общие утилиты, логирование, JSON, файловые операции;
- `UsbScanner` — поиск USB-накопителей и сведений о разделах;
- `LayoutManager` — создание двух разделов и их форматирование;
- `WinPePackager` — подготовка WinPE и PhoenixShell;
- `DataSourceManager` — выбор папок с программами, драйверами и образами;
- `PhoenixShellPackager` — копирование PhoenixShell и конфигураций;
- `InstallerManifestBuilder` — формирование манифеста для InstallerAgent;
- `BuildOrchestrator` — последовательность сборки и логика запуска задач;
- `Ui` — окна, мастера и статус выполнения.

## 6. Функциональные требования

### 6.1 Выбор USB-накопителя

Программа должна:
- показывать список подключённых USB-устройств;
- отображать размер, букву, имя, тип и свободное место;
- предотвращать случайный выбор системного диска;
- требовать явного подтверждения перед форматированием.

### 6.2 Выбор источников данных

Пользователь должен указывать:
- папку с программами;
- папку с драйверами;
- папку с Windows-образами;
- папку с ресурсами PhoenixShell;
- папку с `InstallerAgent`;
- при необходимости готовый билд PhoenixShell.

Поддержка должна быть реализована через:
- выбор отдельных папок;
- возможность указать один корневой каталог, внутри которого UsbBuilder сам ищет `Tools/`, `Drivers/`, `Windows/`, `PhoenixShell/`, `InstallerAgent/`.

### 6.3 Создание двух разделов

UsbBuilder должен автоматически создавать:
- **Раздел 1** — загрузочный раздел WinPE с PhoenixShell;
- **Раздел 2** — NTFS-раздел для данных, драйверов, программ и образов.

Требования к разделам:
- первый раздел должен быть загрузочным;
- второй раздел должен быть NTFS;
- размер первого раздела должен настраиваться, но иметь безопасный дефолт;
- разметка должна выполняться через системные инструменты Windows.

### 6.4 Развертывание PhoenixShell

UsbBuilder должен:
- копировать PhoenixShell.exe и зависимости;
- размещать Qt runtime и плагины;
- создавать или обновлять `winpeshl.ini`;
- обеспечивать автозапуск PhoenixShell вместо стандартной оболочки WinPE;
- копировать конфигурацию и ресурсы, если они выбраны.

### 6.5 Копирование программ, драйверов и образов

На второй раздел UsbBuilder должен копировать:
- программы в `Tools/`;
- драйверы в `Drivers/` по категориям;
- образы Windows в `Windows/`;
- конфиги и обои в `PhoenixShell/`.

Требования:
- структура должна сохраняться;
- метаданные `tool.json` должны переноситься вместе с инструментами;
- путь к программам должен быть совместим с PhoenixShell;
- копирование должно работать с большими файлами.

### 6.6 Манифест для первого запуска Windows

UsbBuilder должен создавать манифест для InstallerAgent, чтобы после установки Windows выбранные программы установились автоматически в тихом режиме.

Манифест должен содержать:
- имя программы;
- путь к источнику;
- категорию;
- silent-аргументы;
- флаг включения;
- дополнительные опции запуска.

После первой загрузки установленной Windows InstallerAgent должен:
- прочитать манифест;
- установить выбранные программы;
- применить драйверы при необходимости;
- завершиться автоматически или перейти в фоновый режим.

### 6.7 Проверка образов Windows

UsbBuilder должен:
- находить `.wim`, `.esd`, `.iso`;
- показывать редакцию Windows, если она определима;
- проверять целостность и наличие файла;
- предупреждать, если образ не подходит для выбранного режима установки.

### 6.8 Логи и отчёт сборки

Программа должна вести подробный лог:
- выбранный диск;
- разметка разделов;
- копирование файлов;
- найденные образы и программы;
- ошибки на каждом этапе;
- итоговый статус.

В конце сборки должен появляться итоговый отчёт:
- успешно ли создана флешка;
- какие папки были скопированы;
- где лежат манифесты и конфиги;
- есть ли предупреждения.

## 7. Требования к интерфейсу

Интерфейс должен быть мастером или экраном с несколькими секциями:
- выбор USB-накопителя;
- выбор источников данных;
- выбор состава флешки;
- параметры WinPE;
- кнопка запуска;
- окно логов и прогресса.

Обязательные элементы:
- список дисков;
- кнопки выбора папок;
- чекбоксы включения компонентов;
- прогресс-бар;
- журнал операций;
- кнопка проверки перед записью;
- кнопка создания флешки;
- кнопка отмены.

## 8. Режимы работы

UsbBuilder должен поддерживать минимум 3 режима:

### 8.1 Полная сборка

Создаёт флешку с:
- WinPE;
- PhoenixShell;
- программами;
- драйверами;
- образами Windows;
- ресурсами.

### 8.2 Только обновление данных

Обновляет только второй раздел:
- программы;
- драйверы;
- образы Windows;
- ресурсы PhoenixShell.

### 8.3 Только пересборка WinPE

Пересоздаёт только первый раздел:
- WinPE;
- PhoenixShell;
- Qt runtime;
- конфигурацию автозапуска.

## 9. Ограничения и безопасность

UsbBuilder должен:
- не разрешать выбор системного диска по умолчанию;
- показывать предупреждение перед очисткой накопителя;
- требовать подтверждения через checkbox или ввод текста;
- проверять доступность выбранных источников;
- не перезаписывать данные без явного согласия;
- не использовать неподтверждённые пути вне выбранных папок.

## 10. Технические требования

### 10.1 Язык и библиотека
- C++20;
- Qt6 Widgets;
- CMake;
- MSVC 2022.

### 10.2 Обязательные технологии
- `std::filesystem`;
- `std::unique_ptr`;
- `std::optional`;
- RAII;
- JSON для конфигураций;
- WinAPI;
- `DiskPart`;
- `DISM`;
- `BCDBoot`;
- `robocopy` или аналог для надёжного копирования.

### 10.3 Архитектурные требования
- отсутствие глобальных переменных;
- разделение логики и UI;
- модульность;
- минимум ручных путей в коде;
- конфигурация должна храниться в JSON.

## 11. Данные на диске после сборки

### Первый раздел

Должен содержать:
- WinPE;
- PhoenixShell.exe;
- Qt DLL;
- `winpeshl.ini`;
- плагины Qt;
- логи;
- необходимые системные файлы.

### Второй раздел

Должен содержать:
- `Tools/`;
- `Drivers/`;
- `Windows/`;
- `PhoenixShell/`;
- `InstallerAgent/`;
- манифесты и служебные JSON-файлы.

## 12. Формат входных папок

### 12.1 Программы

Каждая программа должна иметь:
- exe-файл;
- иконку;
- `tool.json` или эквивалент.

Пример структуры:

```text
Tools/
  AIDA64/
    aida64.exe
    icon.png
    tool.json
```

### 12.2 Драйверы

Рекомендуемая структура:

```text
Drivers/
  ChipSet/
  GPU/
  Network/
  Audio/
  Storage/
```

### 12.3 Образы Windows

Поддерживаемые форматы:
- `.wim`;
- `.esd`;
- `.iso`.

### 12.4 Ресурсы PhoenixShell

Поддерживаемые папки:
- `wallpapers/`;
- `config/`;
- `resources/`;
- `themes/`.

## 13. Алгоритм сборки

1. Проверить входные данные.
2. Определить USB-накопитель.
3. Получить подтверждение пользователя.
4. Очистить накопитель.
5. Создать 2 раздела.
6. Подготовить WinPE-раздел.
7. Развернуть PhoenixShell.
8. Скопировать программы и драйверы.
9. Скопировать образы Windows.
10. Создать манифест для InstallerAgent.
11. Записать конфиги автозапуска.
12. Выполнить проверку результата.
13. Показать итоговый отчёт.

## 14. Результат работы

После завершения UsbBuilder должен создать USB-накопитель, который:
- загружается в WinPE;
- автоматически запускает PhoenixShell;
- содержит все выбранные программы, драйверы и образы Windows;
- готов к установке Windows и обслуживанию ПК;
- поддерживает автопостустановку выбранных программ после первой загрузки Windows.

## 15. Критерии готовности

Продукт считается готовым, если:
- флешка создаётся в 1 клик после выбора источников;
- структура двух разделов создаётся автоматически;
- PhoenixShell стартует без ручной настройки;
- второй раздел содержит все выбранные данные;
- InstallerAgent получает манифест и может ставить программы в тихом режиме;
- сборка проходит без ручного редактирования файлов.

## 16. Дополнительно

UsbBuilder должен быть ориентирован на сервисные флешки для:
- установки Windows;
- диагностики оборудования;
- обслуживания систем;
- запуска утилит;
- быстрого развертывания наборов программ.

- `UsbBuilder`
- или `PhoenixBuilder`
- или `PhoenixUSBBuilder`

Рекомендуется использовать `UsbBuilder`, если нужен самостоятельный нейтральный бренд, и `PhoenixBuilder`, если приложение входит в одну продуктовую линейку с PhoenixShell.
